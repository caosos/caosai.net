# Contributing to CAOS

CAOS is an experimental governed AI orchestration platform. Contributions, forks, criticism, architecture feedback, and implementation ideas are welcome.

## Best Ways To Help

Useful feedback includes:

- architecture review;
- memory/context design criticism;
- MCP/tool integration ideas;
- E2B/sandbox execution patterns;
- model-routing and cost-control strategies;
- worker-agent orchestration approaches;
- UI/UX feedback;
- security/privacy boundary review;
- documentation cleanup;
- prototype salvage suggestions.

## Current Project Reality

CAOS is an active rebuild and consolidation effort. Some functionality exists in earlier prototypes. Some functionality is planned. Some pieces are being redesigned for a cleaner server-owned build.

Please distinguish:

- built prototype behavior;
- current rebuild work;
- design contracts;
- planned future work;
- private product work.

## CAOSCare Boundary

CAOSCare is a product direction built around the CAOS architecture. Public discussion of the concept, safety boundary, and high-level architecture is welcome.

Do not request or publish:

- private CAOSCare implementation code;
- real resident/staff data;
- facility-specific records;
- private deployment details;
- sensitive screenshots or logs.

## Issues

Good issues are specific and actionable.

Examples:

```text
Memory bin schema: suggest separating raw records, summaries, and retrieval indexes.
```

```text
Model routing: add a policy for cheap inspection workers and strong synthesis review.
```

```text
Visual evidence: README should surface screenshots more clearly.
```

## Pull Requests

Pull requests should be bounded.

Preferred PR types:

- docs cleanup;
- architecture diagrams;
- test/smoke harnesses;
- modular extraction proposals;
- small isolated implementation patches;
- security/privacy improvements.

Avoid:

- unrelated refactors;
- silent behavior changes;
- removing existing capability without replacement;
- exposing secrets or private product data;
- large monolithic rewrites without a migration plan.

## AI-Agent Contributions

If you are using an AI coding agent:

- inspect before writing;
- cite files you inspected in your PR description;
- state exactly what changed;
- avoid claiming a feature works unless you tested it;
- include acceptance criteria;
- stop on uncertainty rather than inventing facts.
